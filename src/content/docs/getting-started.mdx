ImageResizer is an IIS/ASP.NET HttpModule that intercepts image requests, applies transformations via URL query parameters, and caches the results to disk. You add commands to image URLs; it handles the rest.

<Tabs>
  <TabItem label="Version 5 (recommended)">

## Install v5 via NuGet

Open the NuGet Package Manager Console in Visual Studio (**Tools > NuGet Package Manager > Package Manager Console**):

```powershell
PM> Install-Package ImageResizer.WebConfig
PM> Install-Package ImageResizer.Plugins.Imageflow -pre
PM> Install-Package Imageflow.NativeRuntime.win-x86 -pre
PM> Install-Package Imageflow.NativeRuntime.win-x86_64 -pre
PM> Install-Package ImageResizer.Plugins.HybridCache
```

`ImageResizer.WebConfig` handles the Web.config HttpModule registration. The native runtime packages contain `imageflow.dll` — the Rust image processing library that replaces GDI+.

### Configure Web.config

Add the Imageflow and HybridCache plugins to your `<resizer>` section:

```xml
<resizer>
  <plugins>
    <add name="Imageflow" />
    <add name="HybridCache" />
  </plugins>
  <hybridCache cacheLocation="C:\imageresizercache\"
               cacheSizeMb="1000" />
</resizer>
```

The `cacheLocation` **must be outside your web root.** Unlike v4's DiskCache, HybridCache stores files in an arbitrary directory with precise size limits.

**Requires .NET Framework 4.8** and IIS 7+. See the full [v5 install guide](/docs/v5/install/) for details.

## Install v4 via NuGet

```powershell
PM> Install-Package ImageResizer.WebConfig
PM> Install-Package ImageResizer.Plugins.DiskCache
PM> Install-Package ImageResizer.Plugins.PrettyGifs
```

`ImageResizer.WebConfig` adds the required `Web.config` entries automatically (it only adds, never deletes).

### Manual Web.config setup

If you prefer manual configuration, add:

```xml
<configuration>
  <configSections>
    <section name="resizer"
             type="ImageResizer.ResizerSection,ImageResizer"
             requirePermission="false" />
  </configSections>

  <resizer>
    <pipeline fakeExtensions=".ashx"
              defaultCommands="autorotate.default=true"/>
    <plugins>
      <add name="DiskCache" />
    </plugins>
  </resizer>

  <system.web>
    <httpModules>
      <add name="ImageResizingModule"
           type="ImageResizer.InterceptModule"/>
    </httpModules>
  </system.web>

  <system.webServer>
    <validation validateIntegratedModeConfiguration="false"/>
    <modules>
      <add name="ImageResizingModule"
           type="ImageResizer.InterceptModule"/>
    </modules>
  </system.webServer>
</configuration>
```

**Requires .NET Framework 4.5+** and IIS 7+. See the full [v4 install guide](/docs/v4/install/) for details.

## Verify the installation

Browse to `/resizer.debug` on your running site (e.g., `http://localhost:5000/resizer.debug`). This self-diagnostics page shows installed plugins, configuration, and any issues. Bookmark it — it's the first place to check when something isn't working.

## Resize your first image

Add query parameters to any image URL on your site:

```
/images/photo.jpg?width=300&height=200&mode=crop
```

ImageResizer intercepts the request, generates a cropped 300x200 version, caches it to disk, and serves it. Subsequent requests for the same parameters are served directly from the cache.

### Key parameters

| Parameter | Example | Effect |
|-----------|---------|--------|
| `width` | `?width=400` | Scale to fit within 400px wide (aspect ratio preserved) |
| `height` | `?height=300` | Scale to fit within 300px tall |
| `mode` | `?mode=crop` | `pad`, `crop`, `max` (default), `stretch`, or `carve` |
| `format` | `?format=webp` | Convert to a specific output format |
| `quality` | `?quality=85` | JPEG/WebP compression quality (0–100, default 90) |

By default, images are **not** upscaled. Use `scale=both` to allow enlargement (though blurriness will result).

See [Basic commands](/docs/basics/) for the full rundown on resizing modes, alignment, cropping, filters, and format conversion.

## Caching matters

Every production deployment needs disk caching. Without it, ImageResizer decodes and reprocesses the source image on every request. A single image decode can require 50–100 MB of contiguous RAM, which limits concurrent processing.

- **v5:** HybridCache writes to a directory outside the web root with precise size limits. Throughput scales to hundreds of thousands of variants.
- **v4:** DiskCache writes to `~/imagecache/` with a hash-tree structure and lets IIS serve cached files as static content.

If you installed via NuGet with the commands above, caching is already included. Verify it's active on the diagnostics page.

## Using MVC or Web API?

Do **not** wrap ImageResizer in an MVC Action or custom HttpHandler. Application frameworks are designed for HTML/JSON, not large binary payloads. ImageResizer's HttpModule integrates directly with IIS for efficient static file delivery and disk caching — wrapping it in an Action loses all of that.

## Using .NET 6+?

Skip ImageResizer entirely and use [Imageflow Server](https://github.com/imazen/imageflow-dotnet-server) — it's the same Imageflow engine as a middleware for modern .NET, with cross-platform support (Windows, Linux, macOS).
